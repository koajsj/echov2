## 未来数据迁移白名单

用户名与Echo UUID仅在明确权属验证和唯一性冲突审查后迁移，不能凭数据库里相同用户名认定新账号所有权。旧系统不存Echo密码，新系统必须由本人重新设Argon2id密码。管理员身份需重新安全绑定，不复用Synapse管理员token或旧浏览器session。

联系人关系、管理员设置、运营聚合结构可审查后迁移；敏感备注/私人收藏必须用户设备解密后重新加密，不能直接进入新明文字段。IP/浏览记录需核对原采集依据、保留期限和迁移用途，不把旧数据无期限复制。每项迁移有来源/版本/数量/失败清单与用户确认，不先导入再猜归属。

禁止直接迁移MXID、Matrix房间/事件模型、Matrix设备身份/私钥/密文、Group State、ratchet、原有信任关系。没有Matrix协议“兼容层”或新旧消息双中继。

## 用户历史转换

仅在用户设备上：旧Matrix原生客户端分页读取并解密→核对历史覆盖、附件、删除墓碑/权限→用户预览并明确确认→新系统独立加密归档或明确的迁移会话MLS加密副本。服务器不解密旧消息，不将旧event作为新Native原生消息。

默认选择只读加密历史归档；若用户明确选择发布到新迁移会话，必须标记原始来源/原时间/迁移操作者，不能伪装原作者发送或保持原密码学证明。迁移是新内容分发，必须重新核对新组接收者和授权；不可自动给新成员原本无权见到的历史。普通备份恢复始终禁止通过重发历史实现，与用户主动迁移分开。

旧消息缺密钥、旧删除状态不完整、来源不可信或分页不完整时，只能列明缺口/停止，不能填充Mock或保证完整。旧数据/旧目录保留只读，直到用户明确确认迁移完成和清理范围；本轮不迁移、不注销、不删除旧数据。
