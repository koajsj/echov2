## MLS/产品硬门槛

| ID / 状态 | 必须提供的证据 | 缺失时的最小替代 |
| --- | --- | --- |
| G1 BLOCKED：浏览器原生实现 | 固定库/provider/features/commit，suite1在Chromium/Firefox/macOS Safari/真实iOS；原生向量与跨实现互操作，内存/包大小/依赖许可证清单 | 不集成加密；OpenMLS不合格可评估ts-mls，但同标准审计/验证 |
| G2 BLOCKED：Commit一致性 | 稳定native staged/merge/discard、并发/无效候选/拒收/重放/Welcome、客户端与DS恢复流程；无私有state的服务端约束明示 | 停发/quarantine、人工重新建组；不伪造valid ACK或自写MLS状态机 |
| G3 BLOCKED：本地事务 | Worker单写者/跨标签、IndexedDB原生变更+outbox/去重原子性、磁盘满/崩溃/旧快照/包消费断点 | 不启用持久聊天和历史恢复；新设备重新邀请，旧state只读或拒绝 |
| G4 BLOCKED：账户/设备/恢复 | 标准Credential授权profile+成熟实现、根pin/变化检测、防重放与撤销、可信设备引导/JWE恢复；覆盖实际leaf公钥 | 仅pending设备；人工完整指纹核对不冒充SAS；恢复不自动继承信任 |
| G5 BLOCKED：成员隔离与删除 | 逐设备Remove/new epoch、冻结过渡、新成员无旧key、原作者编辑/删除、离线checkpoint优先、媒体引用清理 | 停发/禁止旧cache恢复；只报告服务访问撤销/删除待确认 |
| G6 BLOCKED：独立删除证据/灾备 | 独立持久日志与可信最新头、幂等跨存储收据、冻结捕获/外部介质/隔离恢复/回滚演练 | 不自动恢复旧备份、不标完成删除；受限人工停服核验 |
| G7 OPEN：产品/运维参数 | 用户名策略、隐私/日志保留、配额、合法GeoIP、资源实测、供应链/CSP、账号找回与注销政策 | 使用安全关闭/unknown状态，不猜指标、不降低认证或加密 |

各门槛是同一组事实在不同文档的交叉引用，不建立另一套BLOCKED编号。研究本身不解除运行门槛，本轮不运行这些后续验证。

## 第二阶段：核心建设（未开始）

1. **先可行性原型**：隔离客户端密码学模块中选择已修补OpenMLS版本及现有provider，真实WASM API和持久化，验证G1–G4。若失败停止，不写假SDK、不把旧Matrix搬来兜底。原型工具/依赖、构建/浏览器和必要验证须用户另行授权。
2. **可信身份上线**：按审查后profile实现根/设备签发、KeyPackage验证/一次消费/撤销、设备引导/恢复；补客户端public-root pin和持久化。DB权限用新审核迁移增量开放，不修改已执行001/002。
3. **消息与群组**：真实创建组、Add/Commit/Welcome原子投递、应用数据严格codec、native解密与删除/权限门控，一对一/多设备/角色/转让/解散；G2无效候选不能靠SQL计数忽略。
4. **离线与生命周期**：安全cursor/消息receipt、checkpoint重连、附件私有流/配额、删除独立证据/purge重试、定时销毁与注销状态机。先保留拒写开关，完成G5/G6及外部评审后才开放相应业务。

对应修改区域沿用现有职责目录，必要新文件按具体能力创建，不预造大量空接口/抽象。每项交付包括真实权限/未知结果/取消/进度/成功失败UI；源码审查、原子故障验证和用户可见状态分开记录。
